# LoLスキルラボ チャンピオンカタログ・プレイ称号拡張 設計メモ

## 目的

既存の診断結果で候補にできるチャンピオンを代表的な選択肢まで増やし、チャンピオンごとの操作量・照準・判断・マクロ要求を推薦計算へ反映する。結果画面では診断されたプレイ傾向を表す主称号を1件提示する。すべての候補にはLoL Wikiのチャンピオンページへの参照とアイコンURLを付け、画像が取得できない場合も頭文字表示で診断を継続できるようにする。

## スコープ

- 既存14レーン候補に加え、TOP 3、MID 2、JUNGLE 2、BOT 3、SUPPORT 2の12候補を追加する。
- 既存候補と新規候補の全てにWiki URL、WikiのSquare画像URL、難易度判断メモを付与する。
- Wikiに記載される定性的な難しさを、既存の0〜1の `difficultyProfile` と `minimumRequirements` へ写像する。これは公式の数値難易度ではなく、操作量・照準・判断量・マクロ・知識・状況依存性をアプリのモデルへ移した推定値であることをメモに残す。
- `DiagnosticResult` に主プレイ称号1件を追加し、結果画面および結果カードに表示する。
- アイコン表示はWiki URLを第一候補とし、読み込みエラー時はData Dragon URL、さらに失敗した場合は頭文字へフォールバックする。

## データ契約

`backend/data/config/v1/champion_catalog.json` は、既存JSONを上書きせずに追加候補と全候補のメタデータを保持する。`config_loader.py` は既存ファイルを検証した後、このカタログを検証してレーン候補へ結合する。既存のAPIレスポンス契約は維持し、追加フィールドは任意フィールドとして `ChampionLaneProfile` に渡す。

新しいレーン候補は既存と同じ `styleProfile`、`minimumRequirements`、`requirementWeights`、`preferenceProfile`、`difficultyProfile`、タグを持つ。メタデータには `iconUrl`、`wikiUrl`、`difficultyNote` を含める。

## プレイ称号

称号は能力値と嗜好値だけから純粋関数で計算する。ランキング、順位、パーセンタイル、総合点は表示しない。精密操作、先読み、盤面管理、チーム安定、瞬間判断、タスク切替、リカバリー、イニシエート、レンジ操作、リスク選択を表す10種類の説明的な候補から最も適合する1件を選ぶ。スコア自体は内部選択にだけ使い、画面には称号名・説明・関連能力タグのみ表示する。

## 表示

推薦カードの丸い頭文字部分を画像に置き換え、`onError` でData Dragonと頭文字へ段階的に切り替える。結果画面の能力パネル付近に「あなたのプレイ称号」パネルを追加し、主称号1件を見せる。共有カードにも主称号を含める。

## 検証

- バックエンドの設定スキーマ検証で、既存候補を含むレーン候補が25件以上、基礎候補が24件以上であり、全レーン候補にアイコンとWiki URLが存在することを確認する。
- Vitestで称号が1件返り、能力・嗜好の違いで主称号が変わることを確認する。
- フロントの型チェック、テスト、ビルドを実行する。
- ブラウザで診断を完走し、結果画面に1件の称号、推薦候補のアイコン、画像失敗時の頭文字フォールバックが存在することを確認する。
