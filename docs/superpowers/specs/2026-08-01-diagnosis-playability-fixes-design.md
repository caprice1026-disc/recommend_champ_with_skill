# LoLスキルラボ 診断プレイ体験修正設計

## 目的

GitHub Issue #1〜#10で確認された、診断の進行、入力校正、説明、ランダム性、タスク切替、判断シナリオの問題を修正する。利用者が何をすればよいかを迷わず理解でき、練習と本番を区別でき、同じ入力を覚えるだけでは攻略できない診断にする。

## 設計方針

画面の状態遷移は、利用者の明示操作を境界にする。練習完了時は本番を自動開始せず、ラウンド完了画面を表示して「本番を開始する」操作を待つ。開始前のテスト説明には、必要な操作を3段階の短いガイドとして表示する。

入力列、タスク切替ルール、判断シナリオ、反応待機時間は、UIコンポーネント内に固定値を散在させず、`frontend/src/domain/testLogic.ts`の純粋関数とデータ定義から生成する。これにより、ランダム性の制約を単体テストで検証できる。

好み質問は、現在表示中の番号ではなく、回答または個別スキップ済みの質問キー集合で完了を判定する。全問完了前の通常進行を無効にし、既定値で一括スキップする明示ボタンを別に置く。

## 対象範囲

`frontend/src/App.tsx`では好み質問と校正の状態管理を修正する。`frontend/src/features/tests/TestStage.tsx`では、練習・本番遷移、反応、複合入力、予測、注意分配、タスク切替、判断の実装と説明を修正する。`frontend/src/domain/testLogic.ts`にテスト生成ロジックを追加し、`frontend/src/domain/__tests__/testLogic.test.ts`で回帰を固定する。既存のプライバシー境界、スコア計算、推薦ロジックは変更しない。

## 受入条件

QWERを4キーすべて入力しない限り校正が完了しない。好み質問は全問の回答・個別スキップ、または一括スキップのいずれかでのみ次へ進める。練習終了後に本番1問目を自動消費せず、明示的な本番開始画面を表示する。反応待機時間、複合入力列、タスク切替刺激、判断シナリオが試行間で固定循環しない。予測・注意分配は開始前と実施中の表示だけで操作手順を理解できる。タスク切替後の対応表が実際の判定ロジックと一致し、判断テストで同じ状況文を繰り返さない。

## 検証

フロントエンドで`npm.cmd run test:run`、`npm.cmd run lint`、`npm.cmd run build`を実行する。ブラウザでは、ランディングから校正、好み質問、練習から本番、全8テスト、結果画面までを再操作し、Issueの再現手順が成立しないことを確認する。
